# JFA-20 — Strong privileged authentication and session security

- **Factors:** passkeys (WebAuthn via the maintained `@simplewebauthn/server` 14.0.3 / `@simplewebauthn/browser` 14.0.0, ES256/RS256, user verification **required**, `none` attestation) are recommended. An RFC 6238 TOTP authenticator app (HMAC-SHA1, 6 digits, 30 s, ±1 step, checked against the RFC test vectors) is the fallback. Ten single-use recovery codes (stored as keyed HMACs) are issued with the first factor. The TOTP secret is sealed with AES-256-GCM.
- **Relying party:** the RP ID is the hostname of `APP_PUBLIC_URL` and the expected origin is that origin (https only). For the preview that is `justice-for-all-web.onrender.com`. Changing the domain later invalidates passkeys registered for the old one.
- **Enrollment:** the first factor can be added only on a fresh session (≤15 min after an email-link sign-in). Adding more factors, or removing one, needs a fresh step-up. Staff can't remove their last factor.
- **Step-up:** per **session**, valid for 10 minutes (`auth_sessions.step_up_at`, method recorded). WebAuthn challenges are single-use, last 5 minutes and are bound to the issuing session and purpose. TOTP time steps can't be reused. 5 failed attempts in 15 minutes lock all step-up methods, including recovery codes. Every success and failure is audited.
- **Staff gate:** `authorizeStaffRequest(client, session, action)` requires an enrolled factor for any staff route and passes `enforceStepUp` with the session's step-up time into the JFA-21 policy, so privileged actions (publish, withdraw, roles, privacy processing, audit, integrations) need a step-up on this session. Every future admin route must use it.
- **UI:** `/account/security` (needs JavaScript for WebAuthn) and JSON endpoints `/api/account/mfa/{register-options|register-verify|stepup-options|stepup-verify|totp-begin|totp-confirm|totp-stepup|recovery-stepup|revoke}` (same-origin POST, session required, no-store).

## Evidence
`packages/db/tests/mfa.integration.mjs` uses a software authenticator (`tests/helpers/soft-authenticator.mjs`) that produces real CBOR attestations and ECDSA assertions. It covers registration, single-use challenges, a phishing origin rejected, a **stolen second session unable to step up or reuse the owner's challenge**, a replayed assertion rejected, step-up expiry, the fresh-session enrollment rule, TOTP replay, lockout (recovery codes can't bypass it), single-use recovery codes, and the last-staff-factor rule. `tests/totp.test.mjs` runs the RFC 6238 vectors. A local E2E run through the HTTP API covered cross-origin refusal, TOTP enrollment, same-step replay rejection and step-up.
